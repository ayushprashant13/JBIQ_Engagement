Definition

Engagement — Measured and Felt

Engagement has a number and a behaviour. The number tells us if it's working. The behaviour tells us why.
Mathematical
E = Session Depth × DAU / MAU
DAU = app open. Session depth = f(time spent, turns completed). Target: DAU/MAU ≥40% at GA+60. This is the health check — if the number moves, we dig into the behaviour model below to find out why.
Psychological — the Habit Cycle
Motivation (why they care) → Trigger (what brings them) → Ability × Low Friction (can they act) → Variable Reward (what they get) → Investment (loads the next trigger) → ↻ repeats
What indicates engagement is working
Frequency
DAU/MAU, D7 return, D30 return. Retention = the defined behaviour is repeated in trailing 7-day windows.
Value
Successful task completion, repeat of same use case, user-rated helpfulness.
Depth
Multi-turn completion, saved context, task continuation across sessions.
Breadth
Domains used, cross-domain progression.
Moat
Memory created, reminders set, family profiles, saved preferences — accumulated switching cost.
How this cycle maps to everything below
The user already has a Motivation — anxiety ("aaj ka din kaisa?"), aspiration (exam prep), ritual need (morning puja), or practical urgency (scheme deadline). JBIQ doesn't create it, it meets it. Then a Trigger fires. This can be external — a push notification, a WhatsApp message, a festival on the calendar — or it can be internal: the user's own felt need. Kavita opens JBIQ at 6 AM not because a notification told her to, but because not checking feels incomplete. That internal trigger is the goal — external triggers (Hooks in the building blocks below) are the scaffolding that builds toward it. The user acts if Ability is high and Friction is low — voice-first, one-tap, regional language, no blank prompts. These are design decisions in Channels and Homepage surfaces. The action delivers a Variable Reward — reassurance, progress, clarity, social currency. Variable is key: rashifal works because each day is different. Predictable = boring. This is what makes each Loop (daily, event, task) feel worth repeating. Finally, the user makes an Investment — DOB for kundli, resume for prep, family profiles for household tracking — that makes tomorrow's experience better and leaving costlier. This maps to the HVA sequence: Value Realisation → Commitment → Investment → Distribution → Expansion. Each cycle enriches the next. By Day 30, the accumulated investment IS the moat — powered by N=1 Personalisation.

Building Blocks — in priority hierarchy

WHAT → HOW → WHERE

Three axes of execution. WHAT sets priorities. HOW defines rhythm. WHERE delivers and compounds.

WHAT — Value Created

HVA Classes · Sets priorities

1. Value Realisation

First useful outcome. The "aha moment."
Stage 1. Must happen first session. If fails = highest-priority NVA, likely permanent churn. Ref (Hacking Growth): aha moment = must-have status.

2. Commitment

Persistent task. Recurring pull created.
Stage 1-2. Post-task, one tap. Every task arc must include commitment BEFORE resolution — or value exhaustion hits.

3. Investment

User context → better product → switching cost.
Stage 2-3. NOT Stage 1. DOB post 3rd. Resume post 1st practice. Declined → suppress 7d. Stored value makes the product better with use and harder to leave.

4. Distribution

User shares. Advocacy + acquisition.
At peak value moments, not referral prompts. Every share preserves context + language + next action for recipient.

5. Expansion

2nd+ domain. 3-4× retention lift.
In-app ONLY. Never push/WA. Suppress after 3 ignored. One domain well > three resented.

HOW — Recurring Patterns

Loops + Hooks · Defines execution rhythm

Daily Loop

Same time, same action, every day. Rashifal, panchang, digest.
Under 60s. Forgiving streak (5/7). Anchored to morning/evening rhythm. Verticals: Astrology, Devotion, News.

Event Loop

External moment fires trigger. Match, festival, deadline.
Stronger than app-generated triggers. Seasonal intensity. Verticals: Cricket, Entertainment, Devotion (festivals). Ref (Dream11): real-world urgency.

Task Loop

Persistent multi-day task. Dose, refill, status.
High-stakes. Adherence tracked, not streak-punished. Verticals: Health, Govt (deadline tracking).

Life Loop

Aspiration-driven. Progress visible over weeks.
Hard deadline creates urgency. Score improvement drives return. Weekly consistency. Verticals: Jobs, Career prep, Education.

Episodic Loop

Low frequency, high trust. 5-7 day gaps normal.
Returns when task fires, not daily. Trust not habit. Verticals: Govt Schemes, Local Services. Strongest WOM when payout lands.

Hooks (pull-back mechanisms)

4 types: Task-triggered, Scheduled, Event, Behavioural (streak/lapse).
Task: PN→WA escalation for high-stakes. Scheduled: 6 AM rashifal, evening digest. Event: match toss, festival, deadline. Behavioural: streak at risk, score dropped. External triggers evolve into internal triggers — the goal is the user opens without being prompted.

WHERE — Delivery + Moat

Surfaces + Intelligence · Compounds over time

Channels

PN (default, ~20% OEM delivery) → WA (task-escalation) → In-app (discovery) → Voice (cross-cutting C/D).
OEM-segmented delivery = first-class metric. WA: send value, not reminder. Interest-inferred: NEVER WA. Voice: primary mode for C/D — amplifies every lever.

Homepage → "Today for Me"

9 surfaces. Evolves from persona-first (New) to personalised daily briefing (Retained). Click to see all surfaces.
Surfaces (in priority order by lifecycle state):
① Updates — priority anchor for action-today items. "Bill due in 3 days." "Vrat tomorrow." Hidden at D0, active when something is actionable. Like Swiggy's active order card or Meesho's order status — time-sensitive at the top, always.
② Continue — unfinished threads. Resume tasks. Progress bars. "Aapki prescription pending hai." Active D7+ when tasks exist. PhonePe shows incomplete KYC / pending transfers prominently. Respects user's unfinished business.
③ Value Ribbon — persistent proof of value: "Saved ₹X, Y tasks completed." Builds over time. CRED shows cashback earned. Makes accumulated value visible. CTA: tap → full recap of what you've done and saved.
④ Your Assistants — 12 domain avatars, signal-ordered. Always visible, never cold. Entry to verticals. D0: ordered by cohort affinity (Seg C F 35-50 → Astro first). D30: ordered by usage frequency. The reorder itself is the personalisation signal.
⑤ For You — personalised feed. 3-5 cards. Variants: vertical content, partner offers, predictions, alerts, local relevance. Dream11 shows match cards with countdown timers — time-pressure CTAs. Each card should have a specific CTA: "Dekhein" / "Set reminder" / "Check now" — not generic "Open."
⑥ Discover — surface unfound value. Must feel earned, not pushed. 3 items, rotating. Hidden when nothing earns the slot. JioSaavn's "Made for You" sits below active content. Discovery is always below active tasks/updates — never above.
⑦ Moments — shareable celebrations. Festival wishes, streak milestones. WhatsApp share CTA. Active at milestones and festivals. Templates need editable last line to feel personal, not corporate.
⑧ Recap/missed — "Since you were away: 3 rashifals, 1 vrat, scheme deadline passed." For returning users (7+ day gap). Shows what the product did while they weren't there. Spotify Wrapped principle: personal history as value. But daily-scale: what you missed, not what you did.
⑨ Multimodal Input — voice, text, image, doc. Always visible. Voice tip at D0/D7 (teaching states). Context-aware placeholder. Voice mic should be primary CTA for Seg C/D. Text for Seg B.
Card ordering rule: Urgency first (Updates), then unfinished (Continue), then value proof (Ribbon), then today's content (For You), then growth (Discover). Returning users see Recap before For You. Festival states can override: festival content takes hero position.

Gamification

Incentivises habit-building behaviour — not just daily opens. Rewards = more value, not badges.
Behaviour-based streaks (not just daily):
· 2+ verticals interacted with in a week → "Explorer" milestone
· 3+ sessions in a week → consistent user signal (linked to Engaged stage definition)
· Domain-specific: rashifal 5/7 days, exam practice 5 sessions/week, adherence % for health
· Cricket prediction accuracy over a series, not per-match

Progress indicators: Kundli completion %, exam readiness score, scheme tracker status — make investment visible.

Rewards: Always more value, never tokens. 14-day streak → deeper kundli. Mock milestone → weak-topic extra set. Scheme completion → next eligible scheme surfaced.

Leaderboards: Cricket prediction (social proof, IPL-seasonal). Study groups (mutual accountability). Not used for utility verticals (health, schemes — these are private).

Principle: Gamification amplifies utility. It cannot substitute for it. Build repeatable value first.

N=1 Personalisation + NBA

UCP warm-start → 4 memory types → 3 data tiers → individual model → NBA decisioning.
UCP: language, city, rashi, device from Jio 1P. Memory: Profile, Procedural, Episodic, Extracted. Tiers: Cold (cohort) → Sparse (blended, 1-20 sessions) → Rich (N=1, 20+). NBA at GA: rule-based cohort logic evolving to signal-informed. Accepts HVA classes as action space — decides which HVA to fire, for whom, via which channel. Platform capabilities: Cross-session memory, task resume, context carry-forward — these enable loops, not define them. Rule: explicit beats inferred. Wrong memory worse than none.

When the loop breaks

Re-engagement & Pre-churn Capture

The lifecycle has a forward path and a decay path. This section owns what happens when a user drifts — the interventions, the channels, and critically, when to stop.
User with active tasks goes silent (3-7 days)
Highest-ROI re-engagement. Send the value, not a reminder — today's rashifal, the scheme deadline, the dose they missed. The content IS the re-engagement.

Channel: WA Task-triggered
Stop: 3 ignored WA messages → accept drift. Do not increase frequency.
User without tasks goes silent (3-7 days)
Much harder — no hook to pull. One interest-based PN (strongest signal from session history). If ignored, one WA attempt with time-sensitive content. Then stop.

Channel: PN → one WA Interest-inferred
Stop: one PN + one WA. No commitment was earned, so no right to persist.
Frequency declining (was daily, now every 3-5 days)
Batch risk score rising. Surface value in primary domain via PN first — don't escalate to WA yet. If primary domain content doesn't arrest decline, surface a new capability or adjacent content.

Channel: PN Domain-specific value
If content freshness is the cause (rashifal feels templated), the fix is content quality — not more notifications.
Task completed, no follow-on commitment (value exhaustion)
A design failure in Stage 2, not fixable in Stage 3. If the user checked scheme eligibility and got the answer but no deadline alerts were set, there's no structural return reason. Prevention: every task arc must include a commitment moment before resolution.

Design debt
No downstream intervention compensates for a missing commitment HVA.
User mutes notifications or deletes a task
The user just told you to stop. Do NOT send more. In-app on next visit: "Notifications adjust karein?" Offer control, not persuasion. Sending a re-enable nudge after a mute is the fastest path to an uninstall.

Respect the signal In-app only
Dormant 14+ days → win-back
Festival-anchored content if seasonal ("Navratri vrat schedule ready hai"). Capability drumbeat if new features launched ("JBIQ ne nayi cheez seekhi"). Max 1/week on WA. Only if user had active tasks when they went dormant. After 3 ignored: stop. Accept churn.

WA 1/week max Calendar-anchored
90+ days or uninstall = churned. No further intervention.
The governing principle: every intervention has a stop condition. The cost of over-nudging — notification mute, WA block, uninstall, trust erosion — exceeds the cost of accepting churn. Guardrails measured alongside retention: opt-out rate, mute rate, uninstall rate. A "retention win" that increases opt-out rate is not a win.
